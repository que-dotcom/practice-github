01

GitHubアカウントを作る

まずは各自で進める準備です。

  1. GitHubの登録ページを開き、画面の案内に沿って個人アカウントを作ります。GoogleまたはAppleでの登録も選べます。
  2. 登録中に案内されるメールアドレスの確認を完了します。確認されていない場合、リポジトリ作成などの基本操作の一部が使えません。
  3. ユーザー名を主催者へ伝えます。パスワードや認証コードは伝えません。
  4. 安全のため2段階認証（2FA）を設定し、回復コードを安全な場所に保存することを勧めます。
ここでの確認

GitHubにサインインでき、右上のプロフィールから自分のユーザー名を確認できれば次へ進めます。

根拠：GitHub Docs「Creating an account on GitHub」

02

主催者が練習場所を整える

このリポジトリを使うための設定。参加者は公開URLを確認します。

練習用リポジトリ

que-dotcom/practice-github
公開設定（Public）で、教材と自己紹介のファイルを置きます。

公開サイト

que-dotcom.github.io/practice-github/
GitHub Pagesの設定後に閲覧できます。

① 共同編集者として招待する

主催者がリポジトリの Settings → Access → Collaborators → Add people を開き、参加者のGitHubユーザー名を選んで招待します。参加者は届いた招待を承諾してください。

「公開」と「編集できる」は別です

Publicなら誰でも閲覧できますが、この演習で元のリポジトリに作業ブランチをpushするには、参加者が共同編集者（collaborator）として招待を承諾する必要があります。

② GitHub Pagesを有効にする

主催者が Settings → Pages → Build and deployment で Deploy from a branch を選び、main / (root) を指定して Save。ページに表示される公開URLを開いて確認します。mainへの変更が公開に反映されます。

③ レビューをルールにする（推奨）

主催者が Settings → Branches のブランチ保護で、対象を main にし、Require a pull request before merging と Require approvals を設定します。これで必要な承認を満たすまでマージできません。保護を設定しない場合も、演習では必ずPRとレビューを経て進めます。

根拠：招待 · Pages · ブランチ保護

03

PCで作業する準備

コマンド例はPowerShell、Git Bash、macOSのターミナルで共通して使えるGitコマンドです。

  1. Git をインストールします。エディターには Visual Studio Code などを使えます。
  2. ターミナルを開き、下のコマンドでGitが使えることを確認します。
  3. 初めてGitを使うPCなら、commitに記録する名前とメールアドレスを設定します。メールは公開され得るため、必要ならGitHubの非公開メールアドレス設定を確認してください。
Gitの確認・初期設定
git --version
git config --global user.name "表示したい名前"
git config --global user.email "GitHubに登録したメールアドレス"
認証について

HTTPSでpushすると、ブラウザなどでGitHubへのサインインを求められることがあります。GitHubのアカウント用パスワードをターミナルのGit認証欄へ入れる方法は使いません。画面の案内に従って認証してください。

根拠：Gitのセットアップ · GitHubへの認証

04

cloneして作業ブランチを作る

ここから参加者の実習です。元のリポジトリをPCにコピーします。

入力すると下のコマンドがあなた用に変わります。このブラウザにだけ保存されます。
  1. 作業したい場所でターミナルを開き、下のコマンドを上から順に実行します。
  2. git clone でPCにコピーし、cd でフォルダに入ります。
  3. git switch main でmainを選び、git pull origin main で最新にします。
  4. git switch -c で自分専用のブランチを作ります。code . が使えなければ、VS Codeの「フォルダーを開く」から practice-github を開きます。
コピー → main更新 → 自分のブランチ
git clone https://github.com/que-dotcom/practice-github.git
cd practice-github
git switch main
git pull origin main
git switch -c profile/YOUR_ID
code .
GitHub上のmain→ clonePCのmain→ switch -c自分の作業ブランチ
作業場所を確認

編集の前に git branch --show-current で profile/あなたのユーザー名 が表示されることを確かめてください。

根拠：リポジトリのclone

05

自己紹介を書いてpushする

最初の演習では、各自が自分のHTMLファイルだけを編集します。

  1. リポジトリ直下の profile-template.html をコピーします。コピーしたファイルを members/あなたのGitHubユーザー名.html として保存します。例: members/octocat.html。
  2. そのファイルの見出しと文章を編集して保存します。ブラウザでファイルを開き、表示を確認します。
  3. git status で変更を確認し、自分のファイルだけを git add。commitして作業ブランチをpushします。
変更の記録と共有
git status
git add members/YOUR_ID.html
git commit -m "Add profile: YOUR_ID"
git push -u origin profile/YOUR_ID
3つの違い

save はファイル保存、commit はPCのブランチに変更を記録、push はその記録をGitHubへ送信します。pushしただけではmainや公開サイトには反映されません。

公開される内容に注意

自己紹介には公開してよい名前や趣味だけを書きます。住所、電話番号、パスワード、トークン、秘密鍵は含めません。

根拠：Gitの基本 · commitとpush

06

Pull Requestを作り、仲間がレビュー

変更をmainへ入れる前に、内容を見てもらいます。

  1. GitHubの練習用リポジトリを開き、push後に表示される Compare & pull request を選びます。見えなければ Pull requests → New pull request から選びます。
  2. base: main ← compare: 自分のprofileブランチ を確認します。タイトル例は「Add profile: 自分のユーザー名」。説明には変更内容と確認方法を書きます。
  3. Create pull request を押し、仲間をreviewerに指定します。
  4. reviewerは Files changed で差分を見て、公開してよい内容か、表示が崩れないかを確認します。必要ならコメントや修正依頼を出し、問題がなければ Review changes → Approve で承認します。
作業ブランチ→ PRで提案レビュー・修正→ 承認mainにマージ
レビューとルール

仲間に見てもらう運用と、GitHubが承認を必須にする設定は別です。承認をマージの条件にするには、主催者がmainのブランチ保護を設定します。PRの作者は自分のPRを承認できません。

根拠：PR作成 · 必須レビュー

07

mainへマージし、公開を確認

レビュー後、変更をサイトへ届けます。

  1. 承認と設定されたルールを満たしたら、権限のある人がPRの Merge pull request を押し、確認します。主催者が担当する形でも構いません。
  2. PRが Merged と表示されたら、mainへの反映は完了です。GitHub Pagesの公開処理が終わった後、下のURLで自分のページを開きます。
  3. 次の作業の前にはPCでmainへ戻り、最新の内容を取得します。
次の作業に備えてmainを更新
git switch main
git pull origin main

自分の公開ページ: https://que-dotcom.github.io/practice-github/members/YOUR_ID.html

おつかれさまです

公開がすぐに変わらないときは、しばらく待って再読み込みし、リポジトリの Actions や Settings → Pages で公開状況を確認します。

根拠：PRのマージ · Pagesの公開元

?

困ったとき

止まりやすいところを先に確認しましょう。

招待が見つからない

主催者にユーザー名が正しいか確認します。GitHubの通知と登録メールを確認し、招待を承諾してください。

pushが拒否される

招待を承諾したか、GitHubに正しいアカウントで認証したか、作業ブランチにいるか確認します。git branch --show-current で現在のブランチを表示できます。

code . でエディターが開かない

VS Codeを起動し、「ファイル → フォルダーを開く」から practice-github を選んでください。Gitの作業は続けられます。

公開ページが404になる

PRがmainにマージされたか、Pagesの公開元が main / (root) か、ファイル名の大文字・小文字とユーザー名が一致するかを確認します。公開処理が終わるまで少し待つこともあります。

PRがマージできない

必要な承認がそろったか、変更依頼や競合が残っていないか、ブランチ保護ルールの表示を確認します。レビュー担当者や主催者にPRのリンクを共有してください。
